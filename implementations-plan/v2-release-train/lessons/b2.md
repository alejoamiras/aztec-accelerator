# Lessons — cohort B2 (consent hardening)

## Stage 1: guard default-on + F7 rearm latch

- **Design**: `wireButton` guard flipped to default-on (`opts.guard !== false`); `rearmInputGuard`
  renamed+exported as `rearmClickGuard`; authorize.js re-arms on the queued→active edge via a
  `wasActive` latch (so a steady `active:true` across 1s polls doesn't perpetually push arm-time
  forward). bridge.js + authorize.js only.
- **Testable determinism win**: `guardMs()` reads `window.__CLICK_GUARD_MS__` dynamically, so the
  default-on tests need NO wall clock — set a large window, assert the click is ignored, then set
  the global to 0 at runtime and assert the click fires. Only the F7 promotion test needs a bounded
  real-time decay wait (1.7s) because it must let the load-time arming expire before proving the
  promotion re-arms.
- **Mutation proof**: reverting `opts.guard !== false` → `opts.guard` makes all 5 guard tests fail
  (onboarding/renewal/update-prompt become unguarded; the F7 test's re-arm no longer fires).
  Restoring → 5 pass. Existing authorize/onboarding/update-prompt specs stay green (the mock zeroes
  the guard, so they're unaffected).

### GOTCHA (cost ~10 min): Playwright `reuseExistingServer: true` + `bunx serve` serves a STALE
bundle across mutation runs. The webServer command is `build-frontend && serve`, but on reuse
Playwright SKIPS the command, so it never rebuilds; the already-running `serve` keeps serving
whatever bundle was on disk when it started. During a revert→rebuild→re-run mutation cycle the
reused serve served the FIRST run's bundle, giving a false "5 failed" after I'd restored the fix.
**Fix**: kill the `serve -l 3456` between mutation cycles (or set reuseExistingServer:false) so a
fresh server rebuilds. Manual `frontend:build` is NOT enough because serve was started against the
old bundle. (Run-isolation note: this is my own serve on the hardcoded 3456 — killed by marker; a
parallel agent on 3456 would be a real collision, but the config hardcodes it.)

## Stage 2: update-consent version binding (F8)

- **Design**: `PendingUpdate` type alias (`Arc<Mutex<Option<VerifiedUpdate>>>`) → a newtype
  `PendingUpdateSlot<T>` whose ONLY extractor is `take_matching(&displayed) -> TakeMatching<T>`
  (Match consumes / Mismatch retains + returns pending version / Empty). No unconditional `take`.
  `respond_update_prompt` gains a `displayed_version` param; update-prompt.js echoes the URL's
  `version`. On mismatch: log `SECURITY:`, retain, `renavigate_update_prompt` rewrites only the live
  window's query string (via `window.url()` → `set_query` → `navigate`, so the platform
  `tauri://`/`http://tauri.localhost` scheme is never hardcoded) — the M1 fix (no close+re-show race).
- **Testability trick (the crux)**: `VerifiedUpdate`'s only constructor is network-gated, so it can't
  be built in a unit test. Made `PendingUpdateSlot<T>` GENERIC over a `PendingVersion` trait —
  production is `PendingUpdateSlot<VerifiedUpdate>`, the test uses a `Dummy(&str)`. This makes the
  retain-on-mismatch security property directly unit-testable. Mutation: `Some(v) if v == displayed`
  → `Some(v) if true` makes take_matching consume unconditionally → the mismatch assertion
  (`pending_version()` still Some after a mismatched take) fails. Confirmed FAILED→restored→ok.
- **navigate-on-mismatch is innocuous-untested glue**: the security boundary is take_matching REFUSING
  the install (unit-tested); the re-navigate is UX recovery, hard to test without a full Tauri app, so
  it ships as innocuous per the owner constraint.

### LOCAL-BUILD ENV (recurring, will hit every Rust cohort):
- `cargo` is NOT on the default shell PATH here — `export PATH="$HOME/.cargo/bin:$PATH"` each shell
  (shell state doesn't persist between Bash calls).
- `build.rs` (F-012) hard-fails if `frontend-src/*.js` was edited without `bun run --cwd
  packages/accelerator frontend:build` first — rebuild the bundle before any cargo build/test.
- `build.rs` (tauri-build) also needs the bb sidecar present: `bun run --cwd packages/accelerator
  prebuild` (copy-bb.ts copies from node_modules/@aztec/bb.js → src-tauri/binaries/bb-<triple>).
  Gitignored artifact; must run once per worktree before any cargo build/test that hits tauri-build.
- The bin target is `AztecAccelerator` (not `aztec-accelerator`); commands.rs tests are LIB tests
  (`cargo test --lib`).
