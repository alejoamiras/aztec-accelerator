# Lessons — cohort B2 (consent hardening)

## Stage 1: guard default-on + F7 rearm latch

- **Design**: `wireButton` guard flipped to default-on (`opts.guard !== false`); `rearmInputGuard`
  renamed+exported as `rearmClickGuard`; authorize.js re-arms on the queued→active edge via a
  `wasActive` latch (so a steady `active:true` across 1s polls doesn't perpetually push arm-time
  forward). bridge.js + authorize.js only.
- **Testable determinism win**: `guardMs()` reads `window.__CLICK_GUARD_MS__` dynamically, so the
  default-on tests need NO wall clock — set a large window, assert the click is ignored, then set
  the global to 0 at runtime and assert the click fires. Only the F7 promotion test needs a bounded
  real-time decay wait (1.7s) because it must let the load-time arming expire before proving the
  promotion re-arms.
- **Mutation proof**: reverting `opts.guard !== false` → `opts.guard` makes all 5 guard tests fail
  (onboarding/renewal/update-prompt become unguarded; the F7 test's re-arm no longer fires).
  Restoring → 5 pass. Existing authorize/onboarding/update-prompt specs stay green (the mock zeroes
  the guard, so they're unaffected).

### GOTCHA (cost ~10 min): Playwright `reuseExistingServer: true` + `bunx serve` serves a STALE
bundle across mutation runs. The webServer command is `build-frontend && serve`, but on reuse
Playwright SKIPS the command, so it never rebuilds; the already-running `serve` keeps serving
whatever bundle was on disk when it started. During a revert→rebuild→re-run mutation cycle the
reused serve served the FIRST run's bundle, giving a false "5 failed" after I'd restored the fix.
**Fix**: kill the `serve -l 3456` between mutation cycles (or set reuseExistingServer:false) so a
fresh server rebuilds. Manual `frontend:build` is NOT enough because serve was started against the
old bundle. (Run-isolation note: this is my own serve on the hardcoded 3456 — killed by marker; a
parallel agent on 3456 would be a real collision, but the config hardcodes it.)

## Stage 2: update-consent version binding (F8)

- **Design**: `PendingUpdate` type alias (`Arc<Mutex<Option<VerifiedUpdate>>>`) → a newtype
  `PendingUpdateSlot<T>` whose ONLY extractor is `take_matching(&displayed) -> TakeMatching<T>`
  (Match consumes / Mismatch retains + returns pending version / Empty). No unconditional `take`.
  `respond_update_prompt` gains a `displayed_version` param; update-prompt.js echoes the URL's
  `version`. On mismatch: log `SECURITY:`, retain, `renavigate_update_prompt` rewrites only the live
  window's query string (via `window.url()` → `set_query` → `navigate`, so the platform
  `tauri://`/`http://tauri.localhost` scheme is never hardcoded) — the M1 fix (no close+re-show race).
- **Testability trick (the crux)**: `VerifiedUpdate`'s only constructor is network-gated, so it can't
  be built in a unit test. Made `PendingUpdateSlot<T>` GENERIC over a `PendingVersion` trait —
  production is `PendingUpdateSlot<VerifiedUpdate>`, the test uses a `Dummy(&str)`. This makes the
  retain-on-mismatch security property directly unit-testable. Mutation: `Some(v) if v == displayed`
  → `Some(v) if true` makes take_matching consume unconditionally → the mismatch assertion
  (`pending_version()` still Some after a mismatched take) fails. Confirmed FAILED→restored→ok.
- **navigate-on-mismatch is innocuous-untested glue**: the security boundary is take_matching REFUSING
  the install (unit-tested); the re-navigate is UX recovery, hard to test without a full Tauri app, so
  it ships as innocuous per the owner constraint.

## Stage 3: post-deny cooldown (F9)

- **Design**: `DENY_COOLDOWN = 30s` + per-CanonicalOrigin expiry map on `PendingState`
  (`cooldowns`), recorded at the SINGLE choke points `resolve` (system: timeout/close/backstop) and
  `resolve_active` (user Deny click) — gated on `matches!(decision, AuthDecision::Deny)`. Checked in
  `server/auth.rs::authorize_origin` AFTER the is_approved and headless-deny branches (so approved
  sites and headless are unaffected) → new `ProveError::AuthorizationCooldown`.
- **Wire choice (D-C16)**: `authorization_cooldown` is a **403**, not 429 — deployed old SDKs
  hard-throw on any non-403/503, and a cached denial IS a denial, so 403 keeps them on denied→WASM.
- **Eviction**: evict-oldest at `MAX_COOLDOWN_ENTRIES=64` (not drop-new: drop-new lets a flooder
  disable cooldown for everyone; evict-oldest is self-defeating for the flooder).
- **Testability**: `PendingState::is_cooling_down(origin, now: Instant)` takes an explicit `now` so
  expiry is testable by projecting `Instant::now() + 31s` — no clock injection needed. The public
  `AuthorizationManager::is_cooling_down` passes `Instant::now()`. Same-module tests reach the private
  `state`/`cooldowns`. Recording uses `Instant::now() + self.deny_cooldown` internally; the
  block-immediate-retry tests just check within the 30s window at real `now()`.
- **Mutation proofs (both sides)**: (1) removing the check in auth.rs → the server test regresses to
  `origin_denied` (a looping deny-thread makes it a clean assertion failure, not a 660s backstop
  hang); (2) removing the record in `resolve_active` → `user_deny_cools_down` fails. Both confirmed.
- 237 core + 115 src-tauri lib tests green; fmt + clippy clean.

## Codex review round 1 (5 findings, 1 HIGH) — all fixed

1. **HIGH — stale consent → unattended install**: `respond_update_prompt` persisted
   `auto_update=true` on ALL paths, so a mismatch (refused install) still flipped a user into
   auto-install mode → next background check auto-installs the unconsented version. FIX: persist the
   pref ONLY in the Match arm; on save failure `pending.set(update)` to restore (retry-safe).
2. **MED — cooldown check/insert race**: `authorize_origin` checked `is_cooling_down` then called
   `request()` under a separate lock; a concurrent Deny between them let a just-denied origin
   re-popup. FIX: folded the cooldown check INTO `request()` under the same lock; `request()` now
   returns a typed `RequestError::{Cooldown,TooMany}`; removed the standalone public is_cooling_down.
3. **MED — F8 compile-time claim was FALSE (the E-7/E-8/E-10 meta-pattern, AGAIN)**: `inner` was
   private to the *module*, but `respond_update_prompt` is in the SAME module, so
   `pending.inner.lock().take()` compiled — the bypass I claimed impossible. FIX: moved the slot into
   a child `mod pending_update`, making `inner` genuinely unreachable. VERIFIED: a bypass now fails
   with `error[E0616]: field 'inner' is private`. **Lesson burned in: "only extractor" claims must be
   proven by an actual failed-compile, not asserted — module-private ≠ caller-inaccessible when the
   caller shares the module.**
4. **MED — mismatch re-navigate could strand the prompt**: silent early-return on `window.url()`
   failure left controls permanently disabled (command returns Ok, wireButton doesn't re-enable) and
   future 12h checks dedup against the stuck window. FIX: every failure path in
   `renavigate_update_prompt` now closes the prompt.
5. **LOW — incomplete mutation coverage**: the promotion test passed even with the latch removed
   (guard<poll re-arms mid-interval regardless). FIX: added a STEADY-active test with guard(1500) >
   poll(1000) — without the latch the guard never clears → click starved → fails. Mutation-confirmed.
   (Accepted as-is: the 700ms pin brackets (150,800) rather than exact-700 — DEFAULT_GUARD_MS isn't
   exportable without breaking the @tauri-apps/api import in bun:test, and the bracket catches the
   security-meaningful failures 0/huge; the 60s-timer/window-close deny paths are thin callers of the
   directly-tested `resolve` choke point, not worth a 60s literal-timer test.)
