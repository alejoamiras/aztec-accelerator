## Design locked (post-research of hooks.nsi + main.rs --remove-ca-trust)

- **`--prepare-uninstall` CLI branch** (main.rs, right after the `--remove-ca-trust` branch @ :542):
  early-argv, no GUI, per-step status prints, non-zero exit if incomplete (scripted-caller contract),
  `return`. Calls a new `prepare_uninstall()` doing ownership-checked removal of autostart +
  crash-recovery + (if owned) trust/certs.
- **NSIS_HOOK_PREUNINSTALL** (NEW macro): SAME real-uninstall guard as POSTUNINSTALL (`$UpdateMode <> 1`
  AND canonicalized `$EXEDIR != $INSTDIR`) so an interactive UPGRADE never strips autostart/trust; inside
  the guard `ExecWait '"$INSTDIR\AztecAccelerator.exe" --prepare-uninstall'` (exe alive here). PRIMARY path.
- **NSIS_HOOK_POSTUNINSTALL** (EXTEND): keep the existing certutil/certs trust-belt; ADD the native-inline
  BELT — `reg delete` the Run value + `schtasks /Delete` the crash-recovery task — ownership-checked at the
  NSIS level (parse the Run value's quoted exe token, canonicalize, EXACT-equal `$INSTDIR\...exe`). Belt =
  fires when the exe invocation was skipped/failed (idempotent with the primary).
- **Guard duplication** PRE/POST is intentional (NSIS macros can't share locals cleanly); both compute the
  8.3-canonical $EXEDIR/$INSTDIR discriminator.
- Crash-recovery task must die on the PRIMARY path (recon collision #2: it relaunches the app 1 min after
  quit — a live task mid-uninstall re-spawns the app).

## Codex design review (pre-implementation) — 2 real bugs + polarity, all addressed

Consulted codex on the committed primary before building the belt (one-shot uninstaller). Verdict "do not
ship yet":
- **Real bug A**: POSTUNINSTALL's existing certutil/certs removal ran UNCONDITIONALLY on the real-uninstall
  path → it UNDID the primary's foreign-skip (wiped a copied install's shared CA). FIX: a native FOREIGN
  flag computed from the Run value gates ALL shared removal (certutil + certs + Run + task). Proven by the
  new `foreign Run value ⇒ genuine uninstall LEAVES the shared CA` wine case.
- **Real bug B**: `owned_reference_path().ok()` failed OPEN — no identity ⇒ `read_stored_target(None)` reads
  every healthy entry as ours. FIX: fail CLOSED (leave all) when identity can't be resolved.
- **Polarity FIX**: `Broken`/`Absent` don't PROVE ownership. Three states now:
  ConfirmedOurs (remove all) / NoEntry (remove shared, no entry) / ForeignOrUncertain (leave all). `Broken`
  (maybe a copy's removable-volume entry) + `Unreadable` moved to leave-shared.
- **Task belt = KEEP (codex picked (a))**: a scheduled task persists + fires every minute regardless of exe
  presence, so ownership-checked native `<Command>` deletion is load-bearing. Implemented via
  `AztecStrContains` matching the EXACT element `crash_recovery::task_xml` produces (escaped-domain match,
  deceptive-prefix-safe) + `nsExec` schtasks query. Codex's two-layer testing: the PARSER runs under wine
  with captured-XML fixtures (`parser.test.nsi`: ours/foreign/deceptive/escaped/truncated/empty), the live
  schtasks integration is Windows-CI-only.
- **Absent residual = KEEP + documented**: a second install that never armed autostart is invisible; it
  loses HTTPS state and must re-enable. A per-install registry is the complete future fix.
- **PREUNINSTALL invocation proof**: harness now bundles a stub `AztecAccelerator.exe` and asserts
  PREUNINSTALL actually runs `--prepare-uninstall` on real-uninstall / skips on upgrade.

Open for the code-review loop: whether the CLI must independently `<Command>`-check the crash-recovery task
(codex #4) vs gating on the autostart verdict (defensible — `set_enabled` bundles autostart+recovery; the
NSIS belt already does the independent check for the exe-gone path).
