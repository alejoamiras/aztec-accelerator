Presto visual rebrand ✦ the plan

This plan repaints the whole product as Presto: the landing page, the playground, all five desktop app windows, the icons and the animated tray icon, new fonts, light and dark themes, and "Presto" in the copy people read. It deliberately changes nothing operational: the app still installs, updates, and identifies itself as "Aztec Accelerator" under the hood (installer names, domains, certificates, npm, registry keys). The rename of all that machinery is a separate future project. Nothing merges or deploys: everything lands on a preview branch you can run locally, and opening the pull request stays your explicit call.

Why this size of plan (tier: mid)

On the risk rubric (novelty, blast radius, irreversibility, migrations, external coupling, security sensitivity) this scores zero highs: it is a reversible reskin on a branch that triggers no CI. It still spans three packages plus Rust asset plumbing and about 500 tests that must stay green, so it got the mid treatment: one plan plus a competing outline, two independent reviewers, and a final fresh review.

What the reviewers said

Codex (round 1): rejected the first draft. Four real problems: one consent sentence was factually wrong on Linux, an animation state was modeled as a failure when the product actually recovers, the "nothing operational changes" guard had gaps, and two validation commands would not have run. All four are fixed in this version.
Independent Claude reviewer (round 1): conditional approve. It read the actual icon file bytes and caught that the planned icon tooling would have written a subtly wrong format, so the plan now uses Tauri's own official icon generator. Also: keep the native speed slider and restyle it, and clean up the old-brand source files. All adopted.
Final fresh review (three rounds): a brand-new reviewer with the full decision trail rejected twice more on ever-narrower execution details (this headless machine has no display for the end-to-end run, a theme-switch call could race page load, a test was scheduled before its third data source existed, dark-mode fallbacks for very old macOS), each fixed in the plan, and then gave a clean approve: "no new security, gate-ordering, reuse, or executability blocker."

The phases

Phase 1: toolbox and app brand assets

Pin the two new build tools, draw the new icon artwork, regenerate every app and tray icon with Tauri's official generator plus a small script for the 24 animated tray frames, and bundle the three Presto fonts inside the app with their licenses.

Proves itself by: the full lint plus unit test suite, a new test that checks every generated icon is the right size and format, and the Rust build still compiling against the new files.

Phase 2: the desktop app

All five windows get the Presto look (colors, fonts, real icons instead of emoji), light and dark themes that follow your OS, and Presto naming in titles, tray, and copy. Consent screens keep every safety property they have today, and the certificate wording stays accurate per operating system.

Proves itself by: lint, unit tests (TypeScript and Rust), the 65 mocked UI tests, the identity guard test passing untouched, and a manual pass of every window in both light and dark.

Phase 3: the playground

Presto theme, and the ASCII proving animation is replaced by the spark-orbit dial from the brand book. If the accelerator is unavailable the dial shows "proving in your browser" and keeps going, because that is what the product actually does.

Proves itself by: lint, unit tests including a new suite for the dial, the mocked browser tests, and a production build that includes the new social preview image.

Phase 4: the landing page

The full Presto landing from the brand book: new hero with the live race, the "Why presto?" section, four feature tiles, the trimmed banner, the footer that also disclaims the Aztec Foundation, a working mobile menu, and a social preview card so links stop rendering bare.

Proves itself by: lint, the landing tests (now including a type check the package never had), and a clean production build.

Phase 5: the sweep and the real end-to-end run

A committed test greps the whole repo for leftover old-brand colors and fonts, and verifies every frozen identifier is still byte-identical. Then the real compiled app runs through the 17 WebDriver tests on this machine.

Proves itself by: the sweep test, the full suite, and the WebDriver run all green. If this machine cannot build the WebDriver flavor, that gets your explicit sign-off and becomes the first CI check when you open the PR.

Human context

Two things make this plan safe to run autonomously. First, pushing the branch triggers no CI at all, so nothing costs money or leaks anywhere while work is in progress. Second, an existing test literally pins the frozen identity values, and the plan adds a stronger sweep on top: if the rebrand ever accidentally touched something operational, tests fail loudly.

One honest wrinkle you should know about: until the future operational rename, a person can meet both names. The site says Presto, but the installer they download, the app list entry, and the certificate prompt still say Aztec Accelerator. That is the one open question below.

Open question (needs your call)

Bridging copy at the name seams. Both reviewers flagged that unexplained name mismatches on trust prompts teach users bad habits. Pick one:

  • (a) No bridging copy. Cleanest look, mismatch unexplained.
  • (b) Recommended: one plain sentence at the three seams. Download section ("Installs as 'Aztec Accelerator' until our full rename"), the certificate row in the app, and the update prompt. Honest, cheap, easy to delete after the real rename.
  • (c) Only in Settings, next to Manage certificate.
