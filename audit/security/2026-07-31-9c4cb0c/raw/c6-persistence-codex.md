## Finding 1 — macOS repair preserves attacker-controlled launch arguments and executable overrides

1. **Title.** macOS autostart repair validates only `ProgramArguments[0]`, preserving executable overrides and injected arguments.

2. **Impact factors.** Violates integrity, authorization, and availability. A poisoned per-user LaunchAgent can invoke an unintended executable through `Program`, or invoke the legitimate app with an unintended maintenance flag such as `--remove-ca-trust`. The latter removes the current user’s app-specific CA trust and exits before starting either listener; a foreign executable could instead impersonate the localhost service and potentially receive private transaction witnesses. Blast radius is the current macOS account, its browser trust stores, and requests sent to the impersonated listener. Attack vector is local filesystem modification or an over-privileged management tool; complexity is low; privileges required are write access to the user’s LaunchAgents directory; user interaction requires one normal launch or explicit re-enable, followed by login/job launch.

3. **Evidence confidence.** High.

4. **OWASP / CWE.** OWASP A05:2025 Injection; [CWE-88 Argument Injection](https://cwe.mitre.org/data/definitions/88.html). [CWE-20 Improper Input Validation](https://cwe.mitre.org/top25/archive/2025/2025_cwe_top25.html) is the applicable current Top-25 umbrella.

6. **Missing control.** The owned plist schema is not validated. Before classifying or healing, the code should reject a top-level `Program`/`BundleProgram` override and require exactly the expected `ProgramArguments` shape, or explicitly delete execution-affecting overrides and extra arguments while preserving safe recovery keys.

7. **Exploit story.**

   1. A same-user process writes a valid plist containing `ProgramArguments = ["/old/gone/AztecAccelerator", "--remove-ca-trust"]`.
   2. The user manually opens the genuine app.
   3. Startup repair sees only the missing first element and rewrites it to the genuine executable.
   4. The second argument survives the repair.
   5. At the next login, launchd starts the genuine app with `--remove-ca-trust`.
   6. The app removes its CA from browser trust stores and exits without starting HTTP or HTTPS. The poisoned argument repeats on subsequent logins.

   Alternatively, a retained `Program=/Users/alice/.cache/foreign` causes launchd to execute that binary even while the UI classifies `ProgramArguments[0]` as healthy.

8. **Preconditions.** macOS; the attacker or management component can modify the current user’s LaunchAgent; the entry is subsequently repaired, re-enabled, or launched. No administrator privilege is required.

9. **Why mitigations fail.** The `plist` parser prevents malformed XML but does not validate launchd semantics. Desired-path safety checks cover only the replacement path. Atomic writes and symlink refusal protect the destination, not the retained dictionary contents. Windows and Linux explicitly reject trailing arguments, but the macOS implementation has no equivalent check.

## Finding 2 — Forged AppImage environment can capture Linux persistence

1. **Title.** `$APPIMAGE` provenance validation is bypassable by choosing `$APPDIR` as an ancestor of the genuine executable.

2. **Impact factors.** Violates integrity and authorization by making the app install a foreign executable as its `.desktop` and systemd recovery target. It also affects availability and can violate confidentiality if the foreign process claims ports 59833/59834 and receives private witness-bearing requests. Blast radius is the current Linux account and browser transactions sent while the impostor owns the listener. Attack vector is local environment manipulation; complexity is low; no administrator privilege is required, but the attacker must control the environment of an Accelerator launch and place an executable at the selected path. No user interaction is needed when a previously enabled entry is naturally `Broken`; otherwise the user must enable or repair autostart.

3. **Evidence confidence.** High.

4. **OWASP / CWE.** OWASP A08:2025 Software or Data Integrity Failures; [CWE-807 Reliance on Untrusted Inputs in a Security Decision](https://cwe.mitre.org/data/definitions/807); secondary CWE-20, which is in the [2025 CWE Top 25](https://cwe.mitre.org/top25/archive/2025/2025_cwe_top25.html).

6. **Missing control.** There is no trustworthy binding between the AppImage file and the mount represented by `APPDIR`. Containment of `current_exe()` beneath an environment-selected directory is not provenance. The target must be derived from trusted runtime/mount metadata or the environment values must be ignored unless their relationship can be independently verified.

7. **Exploit story.**

   1. Start on Login is enabled, but its stored target becomes broken after a relocation or update.
   2. The attacker places an executable at `/home/alice/.cache/accelerator-impostor`.
   3. The attacker launches the genuine native app as `APPDIR=/usr APPIMAGE=/home/alice/.cache/accelerator-impostor /usr/bin/AztecAccelerator`.
   4. Because `/usr/bin/AztecAccelerator` starts with `/usr`, the provenance check accepts the forged pair.
   5. Automatic repair rewrites the `.desktop` entry to the impostor.
   6. Rearming subsequently writes the same impostor into the systemd user service.
   7. At login or after a failure, the impostor starts under the Accelerator’s persistence identity and can bind the localhost listener before the legitimate app.

8. **Preconditions.** Linux; attacker controls the environment of one app launch and can create an executable file; an existing owned entry is `Broken`, or the user invokes enable/repair. The no-interaction path requires the naturally broken-entry condition.

9. **Why mitigations fail.** Canonicalization only normalizes the attacker’s chosen ancestor. Existence and `autostart_path_is_safe` checks establish syntactic safety, not identity. The implicit-arm gate intentionally permits `Broken` entries; after the heal, the malicious target is classified as healthy and matching. Quoting prevents directive injection but safely serializes the wrong executable.
